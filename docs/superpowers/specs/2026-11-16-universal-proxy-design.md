# 通用 WSL 代理预览版

用户请求：面向开源用户发现任意代理，重点让 WSL 内通用命令行和 Codex 等 AI 工具真正使用正确代理；可单独建立新版本，验证适用性后再采用。延续“不堆叠冗余防御”的约束。

采用独立 feature/universal-proxy 分支及独立预览包，保留 v0.1.0 主分支/发布资产。当前用户指令授权此扩展及验证，不重复进行原工具的设计确认。

## 方案

考虑了只扩大进程名列表并直接写上游地址，以及协议验证加稳定 WSL 入口两种方案。选择后者：应用只需认识 HTTP 代理，SOCKS5 上游也能使用；之后上游切换不会改变已配置应用的代理 URL。代价是 WSL 内运行一个轻量 Python 本地转发进程。

## 通用发现

- 软件名称只用于标签和排序，不作为可接受端点的白名单。
- 首先读 Windows 显式系统代理端点，再检查本机真实 TCP 监听端点。全端口检测只针对已经监听的本机地址，不扫描网络或逐个尝试 65535 端口。
- 识别无认证 HTTP CONNECT、显式 HTTPS 代理和 SOCKS5。混合端口优先 HTTP。认证需求/PAC/TUN-only 明确提示，首版不收集密码、不执行 PAC、不改系统网络。
- 默认先验证系统/已知核心候选；没有可用项时自动扩展本机监听检测，用户也可主动完整检测。限并发、单端点和整体时间，显示未完成/未确认数量。
- 本机随机回显验证协议和真实转发。用户点击连接时再通过选中的代理验证 TLS/HTTPS；本机回显被规则拒绝但外网 TLS 成功的系统或手动候选也可用。
- 保留已有 NAT/镜像模式的真实可达性检测和端点归属检查。不把 Windows 回环专用监听偷偷改成另一个网卡上的同端口。

## 稳定 WSL HTTP 入口

- 每个 Linux 用户首次选择一个可用的 localhost 端口并保存；后续保持 URL 稳定。服务仅绑定 WSL 127.0.0.1，不监听局域网。
- 标准库 Python 转发普通 HTTP 及 HTTPS CONNECT，支持 HTTP/HTTPS/SOCKS5 上游。TLS 字节透明转发，不安装证书、不解密流量。
- 上游配置原子更新，每个新连接读取当前配置；已建立隧道不强行切断。
- helper 安装在用户 HOME，GUI 退出后仍运行；WSL 结束后停止，新 shell 读取管理文件时按需启动。提供明确的关闭/回滚行为。
- 管理 URL、上游配置和 helper 属于同一配置事务。回滚恢复上次上游，第一次安装的回滚关闭本工具的新入口。必要时用本机带随机标识的控制请求识别/停止自有服务，不按进程名杀其他程序。
- 日常不记录 URL、请求正文或凭据。诊断仅使用连接计数及目标主机，设置有界记录。

## 应用生效与验证

- Bash/Zsh 新交互与登录 shell 使用统一 http_proxy/https_proxy/all_proxy 大小写变量及必要 localhost 绕过项。
- 检查 no_proxy=*、Git http.proxy、pip PIP_PROXY/配置、npm proxy/https-proxy 等覆盖；保留用户单独配置并报告来源，不批量抹除。
- 针对支持的 Node 版本提供 NODE_USE_ENV_PROXY=1；不改 NODE_OPTIONS、不把所有 AI 客户端误当成 Node 程序。
- Codex 的 .env 行为依据本机版本与官方源码核实，只同步其中代理键；不读取/发送认证文件或发付费 AI 请求。
- 点击应用诊断时在新 shell 中调用已安装的 curl、Git、pip、npm、Node，只做只读网络查询，不安装依赖。成功退出且本机入口观察到对应目标连接时，才标为“通过本工具联网”；成功但未观察到标为“已联网，路径未确认”。
- Codex 显示版本、代理覆盖一致性及明确验证边界；不能把其他客户端测试成功当作模型 API 鉴权成功。
- 现有进程无法被另一进程普遍改写环境。首次采用入口需要重开应用；已使用固定入口的进程在后续新连接中可以跟随上游切换。

## 界面与交付

- 通用代理页显示实际进程、协议、端点和检测来源，默认不要求选择代理品牌；保留筛选和手动地址入口。
- 显示“上游已验证”“WSL 入口地址”“网络验证结果”不同事实；失败时保留具体原因。
- 应用诊断显示每个工具的路径/连接状态和覆盖提示；详细记录留在本机。
- 移动硬盘部分不扩展。本次交付独立预览包、README 范围表、协议/网关/应用测试和预览分支/PR；主分支与旧版保持可用。

## 验收

- 未知进程名的 HTTP/SOCKS5 代理能被识别；控制端口、认证拒绝、普通 HTTP 服务不会被误判。
- HTTP 请求与 HTTPS CONNECT 经两类上游可正确传输；同一 WSL 入口在上游改变后新连接走新代理。
- 关闭和回滚、端口占用、断开上游和 helper 重启有准确结果；没有开放外部监听或绕过 TLS 校验。
- 新 shell 的真实 curl 请求经过固定入口；有代理覆盖的工具被标出。
- 对已有本机环境只做只读检测；安装与代理配置变更在隔离 Linux HOME 中验证，真实用户主动使用时才应用。

# WSL 与移动硬盘工具：设计草案

日期：2026-11-15。状态：用户已批准实现与开源。

用户补充约束：避免冗余的防御性编程。必要的端点验证、可回滚写入、目标设备校验和系统安全移除保留；检查集中在操作边界，不设计多层重复校验、复杂恢复框架或重复确认弹窗。

## 目标

把现有代理切换脚本扩展为中文 Windows 桌面工具。日常使用只需要打开 SakuraCat 或 Clash Verge，再点击“一键连接 WSL”。同一工具提供移动硬盘占用诊断、正常关闭相关程序和 Windows 安全弹出。最终发布通用的 GitHub 开源仓库，提供 README、许可证、测试和便携启动方式。

用户最关心的是少操作、切换可靠、硬盘和数据安全。安全弹出优先于强行清掉全部进程。工具不能承诺在硬件故障、突然断电、应用未保存数据等情况下绝对无损；它能承诺不强制卸载、不绕过系统拒绝、不把失败显示成成功。

## 已检查的现状

- 现有 `proxy_switch.py` 运行在 WSL，已有真实监听端口检测、HTTP CONNECT 随机回显验证、原子写入、校验备份、并发锁和回滚。
- 两个 CMD 启动器写死了发行版和 Linux 用户；现有核心固定使用 `127.0.0.1`，依赖预先存在的配置文件和 shell 加载设置。
- 当前有两个 WSL 发行版，其中一个位于移动硬盘，另一个位于内置盘。移动硬盘被 Windows 报告为 Fixed，不能单凭 DriveType 判断是否可移除。
- 当前没有 Git 仓库、图形界面、发布配置或通用安装说明。
- 本机已有 Windows Python 3.12 和 Tk 8.6；没有可用的 .NET SDK。
- 本文件不记录个人卷标、Linux 用户名、WSL 安装路径、设备序列号或 GitHub 邮箱。

## 方案选择

1. **Windows Python + Tkinter/ttk 界面，WSL Python 执行端（建议采用）。** 复用现有语言和可靠的配置事务逻辑；源代码版无需第三方 GUI 依赖。Windows 原生 API 负责设备检查和安全弹出。开发者选择此方案，待用户确认整体设计。
2. **.NET/WPF 桌面程序。** Windows 集成和界面能力较好，但要重写现有逻辑、准备 SDK、增加跨语言维护工作。

先交付可双击运行的源码版，配置 Windows 自动测试和便携 EXE 打包流程；环境允许时同时产出经过检查的 EXE。程序自身、状态目录和日志默认位于内置盘，不能运行在正在弹出的目标硬盘上。

## 界面与日常操作

中文窗口，清晰的主按钮、状态卡和简短错误说明；详细日志折叠显示。所有耗时操作在后台运行，主线程仅更新 UI。状态不只依赖颜色。缩放、中文路径和空格路径必须可用。

### WSL 代理页

- 显示发行版、Linux 用户、所选代理软件、实际端口、WSL 可达地址和最近结果。
- 主按钮“一键连接 WSL”。另有“重新检测”“关闭显式代理”“回滚上次配置”和“网络诊断”。
- 自动列出已安装发行版；首次确认目标用户并保存选择。多个 Linux 用户时不猜测应当修改哪个 HOME，尤其不默认给 root 写配置。
- 用户可以明确指定 SakuraCat、Clash Verge 或手动端口。两个软件同时运行时，优先匹配启用的 Windows 系统代理；仍有歧义才显示候选选择。
- Codex 配置同步为可选目标，不要求其他用户安装 Codex，不声称修改 .env 会自动刷新所有 Codex 版本或现有进程。
- 成功后提供“打开已加载代理的新终端”；现有终端和任务不会被自动重启。

### 移动硬盘页

- 自动列出可验证的外接磁盘，显示盘符、型号、容量、同盘其他卷和占用情况。记住设备身份而不是只记住 E 盘。
- 主按钮“安全弹出”：检查设备身份与保护条件，然后请求 Windows 正常移除；无占用时一次完成。
- 如有占用，展示已识别程序、相关 WSL 和系统拒绝信息，提供“正常关闭占用并重试”。关闭前显示会影响的程序和 WSL；未保存内容由应用自己的保存提示处理。
- 仅请求可验证相关程序的正常关闭。用户取消保存、程序不响应、后台服务无法正常关闭或占用无法确定时，停止并说明原因。
- 运行在目标盘上的 WSL 需要先保存任务，再执行 sync 和针对该发行版的停止；sync 不等于应用已经保存。只对用户在界面中明确接受的发行版执行停止。
- 其他发行版可能通过 /mnt 路径访问该盘。检查已运行发行版的相关挂载并提供正常卸载/停止的明确选择；不为检查而启动已停止发行版。忙挂载不强制卸载。
- 仅在 Windows 安全移除 API 返回成功后显示“Windows 已允许安全移除，可以拔出”。驱动拒绝、权限不足、超时、设备突然消失均不能作为成功依据。

## 代理检测与连接流程

1. Windows 读取监听端点、所属进程和系统代理；软件配置只能作为候选线索，不能覆盖真实运行状态。无需读取订阅、节点信息或凭据。
2. 依据进程来源识别两个应用，按地址、端口、协议、PID 和启动时间记录候选。避免只按端口数字误判冲突。
3. 在目标 WSL 中检测真实可达地址：先验证 localhost，再按实际路由尝试 Windows 主机地址。网络模式标识仅辅助诊断，连接验证才是依据。
4. 对候选执行有超时的 HTTP CONNECT 随机回显。控制端口、SOCKS 专用端口、认证失败和普通 HTTP 服务不能通过验证。代理禁止本地回显时明确显示“未能确认”，允许用户发起独立 HTTPS 测试补充诊断。
5. 候选唯一或系统代理可明确匹配时自动选择；其他情况保留现状并请求选择。应用前复查端点身份和协议可达性。
6. 在明确的 Linux 用户 HOME 中写入独立管理的代理文件，为 Bash/Zsh 添加幂等的管理区块；仅修改本工具管理的区块。首次创建、后续修改、关闭和回滚都记录原始存在状态。
7. 配置事务采用锁、备份、哈希校验、原子替换、写后校验和失败补偿。显式恢复中断事务时检查当前值与事务记录；存在外部改动就保留冲突，不能覆盖。
8. 在新 shell 验证实际生效的环境变量；把“配置已写入”“本机代理可达”“外网测试结果”分别显示。

NAT 下若代理只监听 Windows 回环地址，单改端口不能修好连接。界面应准确提示限制和可选配置步骤；不自动修改防火墙、开放局域网监听、更换 WSL 网络模式或重启全部 WSL。外网测试由用户触发，展示测试域名、限制时长、验证 TLS，日志不记录认证信息。

## 配置兼容与边界

- 保留原有 CLI 自动检测、状态、关闭和回滚能力；新的 GUI/CLI 使用结构化结果，不能因 input() 卡住后台任务。
- 旧 `7897.sh` 仅在确认是旧工具生成内容时迁移；未知内容保持不动并提示冲突。旧启动文件中的 source 语句需一并识别，防止旧代理在新配置之后覆盖。
- 新公共默认配置不包含个人用户名、发行版名、固定盘符或路径。当前机器的偏好保存在用户本地状态目录，排除在 Git 之外。
- 支持 Bash、Zsh；其他 shell 给出明确说明，不显示全面生效。APT、systemd 服务、Docker 容器和所有既有进程的代理不纳入自动全局改写。
- 关闭功能关闭本工具管理的显式代理；WSL autoProxy、TUN 和其他系统路由可能仍有效，界面和文档如实说明。

## 硬盘身份、安全检查与实现边界

- 由盘符解析卷 GUID、物理磁盘和设备节点，枚举同一物理盘的所有卷。复合/跨磁盘卷以及不能证明安全的拓扑拒绝自动弹出。
- 校验磁盘号、稳定设备标识、卷映射以及 USB/可移除设备属性，不能只看盘符或 DriveType。重新插拔后必须重新获取并核对身份。
- 拒绝系统盘、启动盘、分页文件所在盘、工具自身所在盘，以及身份或保护状态查询失败的情况。
- 仅选择确实对应目标存储设备的可弹出节点，不能任意沿父节点回溯到 USB Hub 或控制器。
- 最终调用 `CM_Request_Device_EjectW`，检查返回码和 veto 信息。请求前关闭本工具自己的扫描句柄。
- 占用诊断为尽力识别：已知 WSL 虚拟磁盘、可验证的相关进程、已知文件可用 Restart Manager；不能把整个目录注册为“递归扫描”。Windows 可能不提供全部占用者，界面不得声称扫描完整。
- 如需要更完整的文件句柄诊断，可在高级选项支持用户自己安装的 Microsoft Sysinternals Handle；不内置其二进制、不自动接受许可证、不使用关闭句柄功能。基础安全弹出不依赖它。
- 正常关闭前重新验证 PID 与进程创建时间，避免进程号复用。无窗口且没有明确正常停止机制的程序仅报告。
- 不实现 taskkill /F、强制关闭文件句柄、强制 dismount、禁用设备替代弹出或后台反复尝试移除。

## 模块与状态

- `app`：Tkinter 窗口、任务队列、可取消的只读检测、确认对话框和结果展示。
- `windows`：WSL 发现、端点/进程清单、磁盘映射、正常关闭和安全移除适配层。
- `proxy`：纯函数候选选择、端点验证、WSL 任务调度。
- `wsl`：Linux 内配置事务、shell 管理区块、备份恢复与环境检查。
- `tests`：使用临时目录、模拟系统适配层和本地网络夹具，覆盖失败路径。
- 本地设置和脱敏日志在用户状态目录；GUI 启动只读取 Windows 清单，不自动切换网络、关闭进程或启动所有 WSL。
- 关键写入/关闭/弹出操作串行，禁止双击重复提交。安全关键步骤开始后不能通过超时 UI 直接启动第二次操作；未知结果需要重新读取设备状态。

## 开源交付

- 建议项目名 `wsl-drive-toolbox`，公开仓库放在当前已连接的 GitHub 账户下。仓库名冲突时选用清晰后缀，不覆盖已有项目。
- 默认 MIT 许可证；README 以中文为主，提供简短英文介绍、启动说明、截图、支持范围、故障排查、开发测试和打包说明。
- 提供 .gitignore、版本号、测试命令和 Windows CI。公共源码及示例不包含实际配置、.env、订阅、备份、设备标识、用户路径或真实诊断输出。
- 旧 PDF 不直接发布，保留在本机；新的公开说明以通用 README 为准。新截图使用演示数据或遮去个人信息。
- 发布前执行测试和敏感信息检查；只能宣称已完成实际执行并通过的测试。未实机测试两个应用同时运行或真实硬盘弹出的部分要明确注明。
- 用户已经请求创建公开仓库和开源，这是发布授权；若 GitHub 凭据/连接缺少仓库创建能力，仅在具体发布步骤需要时说明缺少的权限。

## 验收标准

1. 双击启动中文 GUI，后台检测期间窗口保持响应；空配置和缺少 WSL 都有明确提示。
2. 任一支持的代理单独运行且可从 WSL 到达时，检测实际端口、验证后应用；端口变化后再次点击能更新。
3. 双代理、PAC、无代理、端口被其他进程接管、认证代理、NAT 不可达等情况不误报成功、不写入未经验证的端点。
4. 新用户初始化、重复应用、关闭、回滚、中途失败恢复均不损坏其他配置或吞掉外部变更。
5. 移动盘即使显示 Fixed 也可识别；系统盘、跨盘卷、盘符换绑和查询失败的安全测试全部拒绝。
6. 模拟正常移除、应用拒绝关闭、WSL 占用、系统 veto、超时和设备丢失；只有 API 明确成功才能显示可以拔盘。
7. 实机验收先使用只读扫描和本机代理验证；不为测试擅自终止用户现有任务或弹出当前存有数据的硬盘。真实移除测试应在用户保存工作并明确发起后进行。
8. README 可让陌生 Windows 用户运行和测试，仓库不包含个人环境硬编码和敏感文件。
